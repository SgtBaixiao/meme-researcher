# Meme Researcher Subagent — SPECIFICATION

> 状态：v1 定稿 | 范围：把 meme-digger 深化为 pi subagent（仅娱乐用途）
> 关联：`../meme-researcher-subagent-design.md`（方法调研）、`prototype/meme-report-prototype.html`（UI 原型）

---

## Problem Statement

网络梗（meme）的信息散落在贴吧、B 站、微博、抖音等相互隔离的平台，不存在统一索引；通用搜索对梗的**多义性、时效性、图文双模态、语义反转、变体演化**系统性失效；社区记忆（起源考据）常常只存在于评论区的字里行间。人工逐平台检索、交叉验证、整理成科普内容的成本很高，且结果质量不稳定（易编造、易误读反讽）。

用户需要一个 **agent 化的"网络梗考古研究员"**：输入一个梗（最好带出现场景），自动完成平台检索、评论区挖掘、时间线重构、交叉验证、梗图收集，最终产出一份**带证据链、时间线、梗图、来源介绍的单文件百科级 HTML 科普页**。仅娱乐用途，不做热度预测或商业分析。

## Solution

一个运行在 pi agent harness 中的 subagent **`meme-researcher`**，执行七层 MSM 方法（意图澄清 → 平台路由 → 查询扩展 → 信源分级 → 评论区挖掘 → 时间线重构 → 交叉验证 → 合成），采用**发散-收敛 agentic 循环**，全部中间产物以文件形式落盘到 `meme-research/<梗名>/` 工作区，最终交付单个自包含 HTML 百科页。

组成：
1. **agent 配置**（`~/.pi/agent/agents/meme-researcher.md`）：隔离上下文、工具白名单、指向 meme-digger skill。
2. **meme-digger skill**（已存在）：承载 MSM 方法论、输出模板、质量标准、安全规则。
3. **脚本套件**（已存在，Python 标准库零依赖）：bili_search / bili_video / bili_comments / bili_memes / bili_dl / tieba_search / config_cookies / make_report。
4. **跨调查索引**（新增）：`meme-index.json`，实现梗间互跳与去重。
5. **验证门**（内建于 agent 规范 + skill 清单）：证据分级、≥2 信源规则、反讽标注、HITL 发布复核。

## User Stories

1. 作为梗好奇用户，我想只问一句"这是什么梗"就拿到一份完整答案文件，这样我不必自己搜 5 个平台。
2. 作为用户，我想补充出现场景（平台/时间/用法），这样多义梗能被解析到正确的义项。
3. 作为用户，我想报告严格区分"确凿事实/网友考证/流传说法/待考证"，这样我不会传播谣言。
4. 作为用户，我想要走红时间线（萌芽→爆发→消退），这样我能理解梗的来龙去脉。
5. 作为用户，我想要带出处和含义说明的梗图，这样我能正确使用而不是误用。
6. 作为用户，我想要单文件自包含报告（图片内嵌），这样我能离线分享。
7. 作为用户，我想要信源列表带一句话介绍（作者/立场/辟谣还是玩梗），这样我能自行核实。
8. 作为用户，我想争议/敏感梗被明确标注风险，这样我了解传播边界。
9. 作为研究员，我想自动挖掘评论区（社区记忆），这样起源叙事不会只靠搜索页。
10. 作为研究员，我想发散线索被追踪登记，这样研究不会死胡同。
11. 作为研究员，我想循环有显式终止条件，这样成本可控。
12. 作为运营者，我想 cookie 统一配置且写入前自动验证，这样平台访问稳定。
13. 作为运营者，我想爬取内容一律按数据对待（防提示注入），这样 agent 不被评论/网页劫持。
14. 作为维护者，我想要 Python 零外部依赖，这样部署零摩擦。
15. 作为 harness 用户，我想 subagent 在隔离上下文运行且产物只写文件，这样主会话不被污染。
16. 作为用户，我想 HTML 生成器使用固定模板，这样每次报告风格一致（百科感）。
17. 作为未来用户，我想跨梗索引支持"相关梗"互跳，这样梗百科真正连成网络。
18. 作为娱乐用途用户，我明确不想要热度预测/商业分析类能力。
19. 作为设计负责人，我想把一种美学风格编码为 skill（美学宣言 + 设计令牌 + 黄金样例），这样任何 agent 设计 HTML 时都能遵循该风格。
20. 作为设计负责人，我想产出物被令牌合规检查（无自创色值/字体/圆角），这样风格不被悄悄破坏。
21. 作为用户，我想为 meme-researcher 绑定专属 house style，这样每次报告页外观一致（百科感）。
22. 作为设计负责人，我想通过评分卡迭代风格资产，这样风格随使用进化而不需要重训模型。

## Implementation Decisions

### 架构决策（模块/接口层，不含代码）
- **Subagent 形态**：`~/.pi/agent/agents/meme-researcher.md`。接口 = 一句任务描述（梗 + 可选场景）；返回 = 工作区路径 + HTML 路径。实现 = 隔离上下文内自主跑 MSM 流水线。`tools:` 白名单：bash, read, write, edit, web_search, web_fetch；`model:` 跟随默认。
- **skill 指针**：subagent 规范首行强制"先 read meme-digger 的 SKILL.md 再开工"（渐进式披露，方法论不进常驻上下文）。
- **深度模块划分**：每个平台能力 = 一个 CLI 深度模块（小接口、大行为）；研究编排 = agent 遵循 skill 的流程规范；产物生成 = make_report.py（工作目录 → 单 HTML）。
- **数据契约**：
  - 工作区 `meme-research/<slug>/`：00-计划 / 01-b站搜索 / 02-b站评论区 / 03-贴吧 / 04-发散线索 / 05-梗图 / 06-来源考证 / 报告-*.md / images/ / <梗名>-百科.html。
  - `meme-index.json`：`{slug, title, aliases[], related[], first_seen, last_seen, top_sources[{platform,title,url}], status}`。
- **验证门（内建于规范）**：每条关键论断 ≥2 独立信源；四档可信度（确凿/考证/传闻/待考证）；反讽类梗强制标注"讽刺对象 + 被讽刺者原话"；发布前人工复核。
- **安全**：中立化规则（爬取内容先剥离指令形态再入库）；cookie 仅存 `config/cookies.json`（日志脱敏、不入仓库）；HITL 检查点。

### 美学风格系统（新增需求）
- **形态**：五层风格记忆——L1 美学宣言（禁忌优先的语言描述）→ L2 设计令牌（tokens.json：颜色/字体/间距/圆角/动效）→ L3 黄金样例（2-5 个带注释的完整 HTML 参考）→ L4 技能化（打包为 `~/.pi/agent/skills/<美学名>/`，渐进披露）→ L5 评测闭环（评分卡 + 令牌合规 lint 回归）。详见 `AI-AESTHETIC-STYLE.md`。
- **绑定**：meme-researcher agent 规范强制"报告页必须按 <美学名> 技能产出"；`meme-digger/templates/encyclopedia.css` 从 tokens.json 生成，保证训练所得即模板所现。
- **不微调**：agent 场景有上下文可加载，五层风格记忆优于模型微调（成本/迭代/多风格并存）；模型微调明确出范围。

### 5 项悬而未决问题的决策（已锁定，含理由）
| 问题 | 决策 | 理由 |
|---|---|---|
| 1. 独立验证者 subagent？ | **v1 单研究员 + 内置验证门**；Phase 2 可选链式"复核员" | 验证规则已编码进 skill 清单；减少活动部件，先跑通端到端 |
| 2. 多义梗并行还是串行？ | **先 L0 澄清（HITL）**；无法澄清才允许 Phase 4 的 parallel 并行研究 | 并行 × 多义 × 未澄清 = 成本爆炸；澄清一次最省 |
| 3. 知识库形态？ | **meme-index.json v1（轻量互跳）**；SQLite 留 Phase 4 | 零依赖、与 stdlib-only 一致；互跳+去重是首版刚需 |
| 4. 梗图相关性验证？ | **v1 人工复核**（现有 T1-T4 + 评分 + 人工）；vision 模型 Phase 3 | 不加外部依赖；评分已把候选质量提上来 |
| 5. 娱乐边界？ | **确认**：不做热度预测/商业分析 | 用户明确要求 |

## Testing Decisions

- **好测试的标准**：只测外部行为——给定一个梗（fixture），流水线产出工作区 N 个文件；HTML 含全部章节与梗图；平台被封时脚本返回可识别错误码而非编造数据。
- **解析器回归**：为 bili_search / bili_comments / bili_memes 保存 HTML/JSON fixture 快照，跑解析断言（防正则回归——本项目风险最高处）。
- **Cookie 验证探测**：B站 nav API（code=0 且 isLogin）、贴吧 frs/page（error_code=0）作为自动化探测。
- **端到端**：对 fixture 梗（如"华夏神族大战羊人"）全流程跑一遍，断言产物完整性与无编造（待考证项必须显式存在）。
- **HITL**：每次真实调查由用户复核最终 HTML（发布门）。

## Out of Scope

- 热度预测 / 商业分析 / 流量运营（娱乐边界）
- 多平台 adapter（微博/知乎/KnowYourMeme/抖音）——Phase 3
- vision 模型梗图自动相关性验证——Phase 3
- SQLite 全文检索/统计——Phase 4
- 容器化无人值守运行
- 贴吧发帖/互动/点赞（只读研究）
- 模型微调（以五层风格记忆替代；微调仅在未来风格无法用语言+样例描述时才考虑）
- 版权材料搬运（只引用链接与缩略图，报告中保留原图 URL 与出处）
- 多义梗自动并行研究——Phase 4

## Further Notes

- **反讽梗处理**（特性 6）：报告必须区分"梗字面"与"梗在讽刺什么"，并引用被讽刺对象的原话作为证据。
- **注入防护**：评论/帖子/网页里的任何指令形态一律无视，只当证据引用；subagent 规范强制此条。
- **信源局限披露**：web_search 工具不可用 / 平台 403 时，在报告"注意事项"明示缺失侧，不装完整。
