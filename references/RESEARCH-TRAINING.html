核心论点

T1 — 训练 subagent = 五阶段无梯度课程，不是微调

文献一致指向"训练免梯度"的可行路线：Voyager 用技能库实现终身学习[2]；Reflexion 用语言自反思从试错中学习[1]；《Training Language Agents to Learn from Experience》证明经验可蒸馏为可复用教训[4]；《Closing the Feedback Loop》提出Insight Governance——把反馈提取为语言规则再注入上下文[5]。五阶段：编码→示范→练习→反馈→运行时学习。

T2 — 训练的核心产物是"技能库 + 教训库 + 案例库"

Voyager 的技能库 = 我们的 meme-digger skill 与脚本套件；教训库 = 每次调查后沉淀的 lessons；案例库 = 黄金调查（正例）+ 失败调查（反例）。三者都是文件，不是权重。

T3 — 单代理不够时，用多代理分工（Anthropic 实证）

Anthropic 研究系统：多代理主要因为"花够 token 把问题解出来"；子代理提供分离关注点（工具/prompt/探索轨迹各自独立），单代理串行搜索会失败[6]。meme 多义梗 = 天然并行场景。

T4 — 训练效果必须有评测闭环兜底

评分卡 + 解析器回归 + LLM-as-judge（GPT-4V 美学对齐实证[7]），低分样本回流为反例——"训练"才真正发生。

"训练"对 agent 的含义

在 agent 范式下，"训练"不是更新权重，而是改变 agent 每次运行时读到的上下文与可用工具。三类手段叠加：

手段载体持久性
知识编码skill / agent 配置 / 系统提示静态（随版本迭代）
少样本示范黄金调查案例库（few-shot）静态，可扩充
经验回流教训库 + meme-index（动态注入）运行时增长

推论：subagent 的"训练度"= 编码质量 × 案例覆盖 × 反馈回路闭合度。三者都可测量、可迭代——这正是本报告要设计的内容。

文献基础（六项证据）

① Voyager — 技能库即训练产物

LLM 驱动的终身学习 agent：自动课程 + 技能库 + 迭代自我优化，无人干预地持续获取技能[2]。→ 我们把 MSM 七层、脚本、模板做成 meme-digger skill，等价于它的技能库；每次调查成功的新"打法"（如某平台新端点）应回写 skill。

② Reflexion — 语言自反思（verbal RL）

agent 从试错中快速学习：失败 → 反思文本 → 注入下一轮[1]。Meta-Policy 变体把反思蒸馏为跨任务可复用记忆[8]。→ subagent 每次调查结束强制"复盘块"：哪一步失败、为何、下次怎么做。

③ 经验蒸馏 — 把经历变成教训

交互经验可被蒸馏为可复用教训，提升未来任务表现[4]；Contextual Experience Replay 支持持续学习[9]。→ 调查后把教训写入 meme-research/lessons.md（全局），下次调查前注入。

④ Insight Governance — 免训练的反馈闭环

把世界反馈（任务结果/市场信号）提取为语言规则，以"上下文注入"方式治理，无梯度[5]。→ 我们的评分卡分数 → 提炼规则 → 更新 SKILL.md/教训库：完整闭环。

⑤ Anthropic 多代理研究系统 — 子代理分工实证

研究者子代理各自独立工具/prompt/探索轨迹（分离关注点、减少路径依赖）；多代理有效的主因是"花够 token 把问题解出来"，单代理串行会失败[6]。→ meme 多义梗用 parallel 多研究员；但先做对单研究员，再并行（Anthropic 也指出多代理引入协调/评测/可靠性挑战[6]）。

⑥ LLM-as-Judge — 训练效果的裁判

GPT-4V 审美判断与人类对齐[7]；传统美学度量（对称/连贯/复杂度/对比）可脚本化[10]。→ 报告质量与风格符合度交给 LLM 裁判打分，低分样本进反例库。

五阶段训练课程（meme 搜索专用）

S1 · 编码

领域知识入库

MSM 七层 + 平台路由表 + 信源分级 + 输出模板 → meme-digger skill；脚本套件为深度工具模块

S2 · 示范

案例库（正反例）

黄金调查 2-3 个（如"华夏神族大战羊人"完整链路）+ 失败反例（第一次全收错梗图）

S3 · 练习

分级评测

课程按难度递增：简单梗→多义梗→反讽梗→新梗；每级跑通才升级

S4 · 反馈

Reflexion 复盘

每次调查后自反思 → 教训蒸馏入 lessons.md → 定期回写 SKILL.md

S5 · 运行

运行时学习

meme-index 跨调查知识 + 新端点/新平台打法回写 skill；多义梗 parallel

S1 编码（静态，一次做好）

  • 角色规范（agent 配置）：身份、边界（娱乐）、工具白名单、强制先读 SKILL.md。
  • 流程规范（skill）：MSM 七层 + 发散-收敛终止条件 + 输出模板 + 安全规则（注入中立化）。
  • 工具：8 个脚本 = 深度模块；agent 只学 CLI 接口。

S2 示范（few-shot，质量大于数量）

  • 正例：1-2 个完整"调查-报告"工作区快照（含各阶段文件），供模仿。
  • 反例：明确标注的失败案例——如"无差别下载评论图 → 梗图全错"——并写明修正规则（分级 T1-T4 + 评分 + 复核）。已具真实反例

S3 练习与评测（分级通过制）

  1. Lv1 简单梗：单义、有科普视频 → 验证基本链路（搜→挖→验→HTML）。
  2. Lv2 多义梗：必须走 L0 澄清；评测"义项选择正确率"。
  3. Lv3 反讽梗：评测"是否识别反讽并标注讽刺对象/原话"（伪史宇宙类）。
  4. Lv4 新梗：无稳定记录 → 评测"是否诚实标注待考证、不编造"。

每级：评分卡（完整性/证据/时间线/梗图/风格）≥ 阈值才进入下一级。评分卡+LLM裁判

S4 反馈闭环（训练真正发生的地方）

调查结束强制复盘：成功项 / 失败项 / 教训（可复用规则） / 建议（更新 skill 或脚本）。教训追加进 meme-research/lessons.md；每 5 条教训 → 审查并合并进 SKILL.md。[1][4][5]

S5 运行时学习（越用越强）

  • meme-index.json：每调查登记 slug/别名/相关梗/信源 → 新调查自动关联已有知识。
  • 新端点/新打法（如发现某平台新 API）回写 skill —— Voyager 式技能库增长[2]。
  • 多义梗：主代理 parallel 派出 N 个研究员各挖一义，leader 汇总 —— Anthropic 式分工[6]（Phase 4）。

落地清单（从今天开始）

  • Step 1 · 固化 S1：写 meme-researcher.md agent 配置（角色/工具/强制流程）+ skill 校准
  • Step 2 · 建案例库：把"华夏神族大战羊人"工作区归档为黄金正例；写"梗图全错"反例页
  • Step 3 · 建 lessons.md 与 meme-index.json 骨架（S4/S5 载体）
  • Step 4 · 评分卡落地：5 指标 × 5 分制，每次调查后强制填写；LLM 裁判脚本化（Phase 3）
